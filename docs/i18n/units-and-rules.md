# Units and rules by country and federation

Research for the AFF notes app (content follows USPA, in feet). Collected 2026-11-16 with web search and the
primary documents listed under each section. Every number has a source. "Not found" means it was searched for and
not found in a readable primary source: it does not mean the rule doesn't exist.

**Key finding first:** metric schools don't teach converted USPA numbers. They teach their own round numbers
(DFV: wave-off at 1,500 m, pull by 1,200 m; FFP: open at 1,500 m; Russia: 1,000 m minimum for beginners). 5,500 ft
converted is 1,676 m, and no metric school uses that figure. So a "metres" switch that only converts the feet values
would teach the wrong numbers. The app needs **rule profiles (federations)**, each with its own unit and numbers.

Legend: **ft** = feet, **m** = metres, **mixed** = both are in use (official papers in one, practice or translations
in the other), **?** = not verified (a best guess with the reason given).

Notes:
- Even metric federations keep **wing loading in lb/ft²**: Finland's metric guide states the A/B limit as "1,34lbs/sqft"
  ([SIL guide](https://laskuvarjotoimikunta.ilmailuliitto.fi/skydivers-guide)). Wing loading stays in lb/ft² everywhere.
- Wind is in **knots** (UK), **mph** (USPA) or **m/s** (FFP, Finland, Russia). Unit follows the profile too.
- Aviation context: almost every country uses feet for aircraft altitude; Russia moved to feet above the transition
  level in 2011 and China keeps metric flight levels ([SKYbrary](https://www.skybrary.aero/articles/metric-altitude-reference),
  [ICAO WP176](https://www.icao.int/Meetings/AMC/MA/Assembly%2036th%20Session/wp176_en.pdf)). Skydiving units follow the
  federation, not the air traffic system: Germany and France use feet in aviation but metres on the student altimeter.

## 2. What metric schools actually teach (their own numbers)

For comparison, the app today (USPA, from the content): exit 13,000 ft, wave-off 6,000 ft, pull 5,500 ft, decide by
2,500 ft, cutaway hard deck 1,000 ft, pattern entry 900 ft. USPA sources: AFF pull "5,500 feet" and "You must decide
to cut away by 2,500 feet" ([USPA ISP Cat B](https://www.uspa.org/skydiveschool/B)); "1,000-foot cutaway hard deck"
([USPA SIM 5-9](https://www.uspa.org/SIM/5)).

## 4. How software handles this

**Unit by region**
- CLDR (the data behind ICU, browsers, iOS, Android) keeps a per-territory `measurementSystem`: metric for the
  world, `US` for LR and US, `UK` for GB and MM. The file itself notes it "will be deprecated ... replaced by enhanced
  preferences" ([CLDR supplementalData.xml](https://github.com/unicode-org/cldr/blob/main/common/supplemental/supplementalData.xml)).
- The newer CLDR **unit preferences** are per usage (road, person-height, visibility ...), but there is **no altitude
  or aviation usage** ([CLDR units.xml](https://github.com/unicode-org/cldr/blob/main/common/supplemental/units.xml)).
  So no locale API knows that a German skydiver uses metres while a German pilot uses feet.
- JavaScript: `Intl.NumberFormat(locale, { style: 'unit', unit: 'meter' | 'foot', unitDisplay: 'short' })` formats
  but does not choose or convert. Tested in Node 24: `ru` → "1 500 м", "5 500 фт"; `fr` → "5 500 pi"; `de` → "1.500 m";
  `es` → "1500 m" (no separator for 4 digits); `zh` → "1,500米", "5,500英尺". The TC39 "smart unit preferences"
  proposal (a `usage` option) is still Stage 1 ([proposal](https://github.com/tc39/proposal-smart-unit-preferences)).
  `Intl.Locale` has no measurement-system field in browsers.
- Apple: `Locale.current.measurementSystem` returns `.metric`, `.us` or `.uk` and reflects the user's override
  ([Apple docs](https://developer.apple.com/documentation/foundation/locale)).
- Devices skydivers use let the user pick: L&B Viso II+ has a "Feet/Meter" setup option
  ([manual](https://manuals.online/altimeters/measuring-instrument/viso-ii/user-manual/126j6)).

**Rules by federation (variants)**
- Pilot exam apps ship one question bank per regulator (FAA, EASA, Transport Canada, UK, China) as separate products
  or in-app choices, not one bank with converted numbers ([Dauntless GroundSchool](https://dauntless-soft.com/products/groundschoolCANADA/)).
- Federations themselves print dual units only as a courtesy in translations (DFU English manual, SFF form, CSPA
  technical recommendations); the rule is in one unit.

Takeaway: locale data can pick a **starting guess** for the unit, never the rules. Rules need an explicit profile the
user can see and change.

---

## 5. Recommendation

**Model:** one setting, "rules: USPA / British Skydiving / DFV / FFP / ...", that sets both the numbers and the unit.
A separate unit toggle only for people who want the other unit as a hint ("5,500 ft (1,676 m)"), never as the main number
in a metric profile. Keep wing loading in lb/ft² in every profile. Show the profile name next to every altitude chapter,
and keep "your school's briefing wins".

**Default profile and unit by country** (from the browser region, e.g. `new Intl.Locale(navigator.language).maximize().region`,
not from the app language: a Spanish speaker may be in Spain or in the US):

| Region | Default profile | Unit |
|---|---|---|
| US, MX, CA, BR, CL, CO, IL, AE, SA, EG, IN, TH, ID, JP, KR, AU, NZ, ZA, NL, BE, IE, and anything unknown | USPA | ft |
| GB, IE (optional) | British Skydiving | ft |
| DE, AT, CH | DFV | m |
| FR (and BE-fr optional) | FFP | m |
| RU, BY, KZ, UA | "Metric, DOSAAF-style schools" (with check marks) | m |
| FI | SIL | m |
| PL, CZ, SK, HU, RO, BG, HR, RS, SI, EE, LT, LV, SE, DK, NO, CN | USPA numbers + metric hint, or DFV-like metric profile once sourced | m |
| AR, IT, ES, PT, GR, TR | USPA (ft), metric hint on | ft |

Always let the user change it; remember the choice.

**Federations to support first:**
1. **USPA**: already done.
2. **DFV (Germany)**: complete official AFF handbook in metres with every key altitude (1,500 / 1,200 / 1,700 / 500 m);
   reaches DE, AT, CH. Gap: decision altitude and pattern (AHB Teil I).
3. **FFP (France)**: official 2026 directive with PAC exits, openings, wind limits and brevet A rules.
4. **British Skydiving**: same unit as the app, but different rules (15 kt, 0.8/0.85 lb/ft², Form 330, 16+, A Licence =
   Category 8). Big English-speaking audience; cheap to add.
5. **Russia / Ukraine metric profile**: the app already has RU and UK languages. Official numbers exist only for minimum
   opening (1,000 m) and wind (8 m/s); AFF pull, decision (600 m) and hard deck (300 m) come from schools and methodical
   notes, so mark them `<q-check/>` and add them to the "ask the instructors" chapter.
6. Later: SIL (Finland) as a well-sourced metric reference; CSPA; APF and KNVvL once their documents can be read.

## Summary

1. Metric schools teach their own round numbers, not converted USPA ones: a units toggle alone would teach wrong altitudes.
2. Clearly metric (by federation documents): FR, DE, RU, UA, FI, DK, SE, PL, CZ, EE; likely metric: AT and post-Soviet / Central European countries.
3. Clearly feet: US, CA, UK, ZA, NL; mixed: AR (official exam gives both), IT, ES; many others not verified.
4. DFV: exit ≥3,000 m, wave-off 1,500 m, pull by 1,200 m (L1), no more 1,700 m, canopy work above 500 m.
5. FFP: PAC exit 3,000–3,500 m, open ≥1,500 m; 1,200 m at brevet A, 1,000 m after brevet B; wind 7 / 11 m/s.
6. Russia: legal minimum opening 1,000 m for beginners; schools pull at 1,300–1,500 m; decision 600 m, no cutaway below 300 m (unofficial).
7. Rules that differ: wing loading (BS 0.8/0.85, others none or charts), wind (14 mph, 15 kt, 7–8 m/s), age (16 UK, 18 or parental consent RU), first licence (USPA 25 jumps, FFP 12 jumps, BS Category 8).
8. Wing loading stays in lb/ft² even in metric federations (Finland), and AAD activation is device-set, not federation-set.
9. CLDR/Intl can format and guess metric vs US/UK, but has no altitude usage and no notion of federations.
10. Recommendation: a visible "rules" profile picked from the region (not language), user-changeable; build DFV and FFP next, then British Skydiving, then a check-marked RU/UA metric profile.
